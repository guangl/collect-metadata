# Emby 季集映射规范

制作方、发行方或授权放送平台公布的分季、篇章和集次是核对依据。Emby 的剧集 ID、季号和集号是本地定位。即使来源使用不同编号，也保留现有文件名和 Emby 季集号。TMDB 和 Bangumi 分别保留自己的目录编号。

## 刮削时怎样判断

1. 已有可用标题、简介和主图的分集优先用 Emby 现有资料。旁挂文件只补缺项。
2. 有经过核对的分季映射时，按 Emby 剧集 ID 和季号取对应的 Bangumi 条目。多篇章按播出顺序排列，合并后的正片总序号必须连续。程序用本地集号定位序列中的同一集。已有 Bangumi 分集 ID 或首播日与来源冲突时暂停写入。首播日允许因时区差异相差一天。一文件多集留待人工确认。
3. 没有映射时，TMDB 分集查询优先使用已知的 IMDb 或 TVDB 分集 ID。候选须属于已匹配的 TMDB 剧集，并与来源返回的可核对 ID 相符。按季集号查询时，如果 TMDB 季 ID 或首播日与本地已有证据冲突，保留失败原因。查询不到对应编号时也保留失败原因，等待核对映射。
4. 只有核对到对应季的资料才补季简介和海报。映射季的简介取对应篇章并去除重复段落，首篇封面作为季海报。已有简介和海报保留。现有 `season.nfo` 只在季号匹配且简介缺失或为空时补 `plot`，保留其它内容与原文件备份。

## 如何登记新的映射

先确认整部剧，再核对官方分季、篇章顺序、首播日期和集数。用各篇章第一集、交界集和末集的片名或外部 ID，与候选目录和本地条目交叉核对。尚未播完的季只核对已有集数。剧名相似、季号相同或集数相同都不足以确认跨目录对应关系。来源把整剧并成一季时，整季的简介和海报不能直接用来代表其中某个本地季。

映射文件按 **Emby 剧集 ID → 本地季号 → Bangumi 条目 ID 列表** 编写，例如：

```json
{
  "123": {
    "2": [456, 789]
  }
}
```

把文件挂载到 Web 容器，并将 `EMBY_AUTO_SCRAPE_SEASON_MAP` 指向容器内路径。也可以在[动画番剧目录](ANIME_CATALOG.md)中登记 PostgreSQL 映射。每季 ID 列表按播出顺序写入。制作方页面用于核对映射，刮削时程序直接使用已登记的目录条目。补齐映射后可让仍在重试的任务继续，或从日志核对归档事件后重新入队。
